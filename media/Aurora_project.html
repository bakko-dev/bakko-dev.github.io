// 04 · why domain knowledge is the moat
// structural advantage

WB SEO is not Google SEO — and most AI tools don't know the difference

Wildberries has its own ranking signals, фасетные фильтры, ЧВМ logic, and a search algorithm that weights exact-match keyword placement in the title differently from description. An LLM without WB-specific training produces generic Russian copywriting. Aurora's prompt engineering encodes WB-specific rules as the actual product.
Domain knowledge = the barrier to copy
ЧВМ (частотность, вхождение, место)

WB ranks cards based on keyword frequency in the title, exact match inclusion in the first 100 chars, and position of the keyword. Aurora's title generation enforces these rules automatically — freelancers and generic AI don't.

Фасетные фильтры (facet filters)

WB's category filter system requires specific attributes in structured fields — not prose. Missing a facet attribute means the card is invisible to filtered searches (e.g. "платье › миди › A-силуэт"). Aurora's audit flags every missing facet.

WordStat keyword data

Yandex WordStat is the proxy for WB search volume. Aurora's pipeline ingests WordStat CSVs and cross-references them against the card's current keyword coverage to identify gaps. This is the core of the SEO audit.

Competitive card benchmarking

Top 5 organic results for the target keyword are scraped via Puppeteer on Amvera. Their titles, keyword density, and review velocity are extracted and compared to the client card. The gap analysis is the most actionable part of the report.

AI stack for report generation

Claude for all copywriting and structured analysis — strongest on Russian SEO copy and structured JSON output. Gemini as A/B baseline for title generation. Qwen for bulk classification tasks (keyword categorisation, facet extraction) where cost per call matters. Multi-model approach lets Aurora pick the best tool per subtask rather than committing to one API.

// domain vocabulary

WB seller & marketplace glossary

Terms from the Wildberries ecosystem, seller communities, and marketplace SEO — with definitions relevant to building Aurora.

// card & seo
Карточка товара (product card)
The full product listing on WB — title, description, photos, attributes, price. The seller's primary surface for both organic search ranking and conversion. A poorly structured card is invisible regardless of ad spend. Aurora's core deliverable is an optimised карточка.
Артикул (article number)
WB's unique numeric ID for each product listing. The primary key for Aurora's pipeline — all data fetches, audits, and reports are keyed on артикул. Sellers refer to their products by артикул in all professional contexts.
ЧВМ (частотность, вхождение, место)
Frequency, inclusion, position — the three WB ranking signals for keyword optimisation. Frequency: how often the keyword is searched. Inclusion: whether the exact keyword appears in the card. Position: where in the title/description it appears. Aurora's title generation enforces ЧВМ rules that most sellers and freelancers don't know exist.
Фасетные фильтры (facet filters)
WB's structured attribute system — the sidebar filters buyers use to narrow searches (e.g. "colour: beige", "silhouette: A-line"). Each category has required facet attributes. A card missing a facet value is excluded from all filtered searches using that attribute. Aurora's audit flags every missing facet.
// advertising & ranking
CPM (cost per mille)
WB's ad pricing model — cost per 1,000 impressions. CPM is auction-based: high-frequency keywords like "платье женское" have 12,000+ bidding sellers pushing CPM to 400–500 ₽. Long-tail keywords have 50–300 bidders and CPM of 30–80 ₽. Aurora's keyword strategy steers clients toward the long tail.
Трафаретная реклама
WB's automated placement ad format — the seller sets a budget and bid; the algorithm decides placement across search results, category pages, carousels, and competitor product pages. High reach, low intent signal, no exclusion controls. Contrasted with поисковая реклама (search ads) where the seller targets specific keywords.
Органический ранк (organic rank)
A card's position in unpaid search results — determined by sales velocity, review score, CTR, card quality, and keyword relevance. Positions 4–9 on page 1 are organic. A well-optimised card can organically sit next to brands spending 500k ₽/month on ads. This is the lever Aurora sells.
Аукцион смерти (auction death spiral)
The dynamic where small-budget sellers burn out in high-frequency keyword auctions. As weak bidders drop out, CPM stays high — large sellers raise bids to absorb freed slots. Small sellers fund the floor price and exit with zero conversions. Aurora's pitch: don't play that auction — dominate the long tail instead.
// operations & infrastructure
Amvera
Russian cloud platform for containerised app deployment. Aurora's Puppeteer scraper and Telegram bot run on Amvera. Key issue: 401 token errors on bot deployment resolved via environment variable update. Scraper faces WB HTTP 498 antibot — mitigated by persistent browser session mirroring. HTTP 498 (WB antibot)
WB's custom status code returned when a request is flagged as automated. Triggered by missing browser fingerprint signals, missing cookies, or too-fast request cadence. Aurora's mitigation: persistent Puppeteer session with full browser fingerprint, media sink for photos/video, human-like request timing.
WordStat
Yandex's keyword frequency tool — the industry-standard proxy for WB search volume data (WB doesn't publish its own keyword frequency data). Sellers export WordStat CSVs for their product category and use them to identify high-volume keywords. Aurora's pipeline ingests these CSVs as part of the keyword gap analysis.
Telethon
Python async Telegram client library used for Aurora's community scraping pipeline. Fetches seller community channels not indexed by Telegram's public search. Aurora's sellers_v1/v2/v3 CSV database of 1,000+ seller community entries was built with Telethon-based automation. Used for outreach targeting, not mass-messaging.

Ranked by speed-to-cash, not by upside:

  • Custom bot builds for other CIS businesses pay faster than trying to monetize the TON bot ideas directly. Bot dev is a commodity skill in high demand on Kwork/FL.ru — quote a fixed price, accept TON/crypto or card via a payment bot if the client is flexible.

What are Telegram Stars and can they be monetized?
Answer

Telegram Stars are Telegram's in-app currency. Users buy them with real money (card/Apple Pay/Google Pay) through Telegram itself, and bots/mini-apps can charge Stars for digital goods and services.

How monetization works

  • Bot sends an invoice via Telegram's Bot API (sendInvoice with currency XTR).
  • User pays in Stars, right inside the chat — no external checkout, no card details to handle.
  • Telegram takes a cut on withdrawal to real currency (rate changes over time — worth checking current terms).
  • Withdraw accumulated Stars to real money via Telegram's payout process (Fragment, or direct payout depending on region).

Critical restriction

Stars are meant for digital goods/services only — Telegram disallows using them for physical goods or many real-world services. Bot-delivered digital services (reports, subscriptions, analytics access) fit cleanly — matches a digital-cards/audit product for WB sellers well.

Why this suits the UK-based setup

  • No RU banking, no Stripe/merchant account needed on either side.
  • Seller in Russia buys Stars however they can (own Apple/Google/card access, or via P2P Stars resellers — a common workaround given RU card restrictions).
  • Operator receives Stars, cashes out from UK side, avoiding RU payment rails entirely.
Caveat: Telegram's Stars withdrawal/payout terms and available cash-out regions change periodically, with reports of payout friction in some countries — verify current terms before committing the payment flow to this.

Answer

Да, Wildberries официально разрешает программное взаимодействие через API для управления карточками товаров, но с ограничениями.

Что можно делать через API:

  • Изменять описание товара.
  • Изменять характеристики карточки (цвет, материал, размеры и т.д.).
  • Создавать и обновлять карточки товаров.
  • Загружать и заменять фотографии.
  • Загружать видео.
  • Управлять ценами, остатками, скидками через соответствующие методы API.

Что важно учитывать:

Описание менять можно

  • Используется метод обновления карточки товара.
  • При обновлении карточка обычно перезаписывается целиком, поэтому нужно передавать и те поля, которые остаются без изменений.

Фото напрямую через обновление карточки менять нельзя

  • Поле photos не обновляется методом редактирования карточки.
  • Для фотографий есть отдельные методы Media API (/content/v3/media/file и /content/v3/media/save).

Полностью заменить набор фото можно

  • Метод загрузки медиа по ссылкам заменяет старый набор изображений новым.
  • Если нужно добавить фото и сохранить старые, необходимо передать ссылки и на старые, и на новые изображения.

Если под «подменой фото» вы имеете в виду:

  • для своих товаров в собственном кабинете продавца — да, это предусмотрено API;
  • для чужих карточек товаров — нет, API не предоставляет такой возможности. Доступ ограничен товарами аккаунта, для которого выдан API-ключ.

Если вы планируете автоматизировать это на Python, могу показать конкретные запросы к API Wildberries для:

  • замены описания;
  • массовой замены фотографий;

Для изменения описания используется метод:

POST https://content-api.wildberries.ru/content/v2/cards/update

Важно: Wildberries перезаписывает карточку целиком, поэтому недостаточно отправить только новое описание. Нужно сначала получить текущую карточку, затем отправить обратно все обязательные поля вместе с новым описанием.

Пример на Python:

import requests

TOKEN = "ВАШ_WB_TOKEN"

url = "https://content-api.wildberries.ru/content/v2/cards/update"

headers = {
    "Authorization": TOKEN,
    "Content-Type": "application/json"
}

payload = [
    {
        "nmID": 123456789,
        "vendorCode": "ART123",
        "title": "Название товара",
        "brand": "Мой бренд",
        "description": "Новое описание товара",

            {
                "chrtID": 987654321,
                "techSize": "M",
                "wbSize": "46",
                "skus": ["1234567890123"]
            }
        ]
    }
]

response = requests.post(url, headers=headers, json=payload)

print(response.json())

Практически всегда схема работы такая:

  1. Получить карточку через POST /content/v2/get/cards/list.
  2. Взять из ответа все поля карточки.
  3. Изменить только description.
  4. Отправить обновлённую карточку через /content/v2/cards/update.

Если ваша задача — массово менять описания у сотен или тысяч карточек, можно автоматизировать цикл:

  • выгрузка всех nmID,
  • генерация нового текста (например, через ИИ),
  • пакетная отправка изменений в Wildberries (до 3000 карточек за запрос).

🧠 2) как агент оценивает, кому писать (lead scoring)

📊 у каждого продавца есть score:

Lead Score = Money Loss × Awareness Gap × Size × Ease of Fix

📦 разберём

1. Money Loss

  • слабый CTR
  • плохие фото
  • низкая конверсия

2. Awareness Gap

насколько продавец не понимает проблему
  • новички → высокий gap
  • бренды → низкий gap

3. Size

  • оборот
  • количество SKU
  • позиция в категории

4. Ease of Fix

  • можно ли быстро улучшить (CTR / фото / title)
  • или сложно (логистика / бренд)

🧠 итог

лучший клиент = большой + теряет деньги + не понимает почему + легко исправить
